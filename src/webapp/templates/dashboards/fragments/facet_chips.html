This carries the parts that are not: the chip markup, the active/clear semantics, and the two-column grid. A chip click writes its value into the named field of a filter form and re-submits it — data-action "set-filter-submit" in static/js/actions.js, CSP-clean, no inline handlers. The active chip is marked and clicking it CLEARS the filter (empty data-value), so it doubles as its own clear button. WARNING: The caller must compute counts with SELF-EXCLUSION — a dimension's rollup must omit its own filter. Scope a dimension by itself and every unselected value reads 0 the moment one is picked, which turns the strip from a switcher into a dead end. See blueprint.py::xras_fragment. WARNING: Values that cannot round-trip through the form must not become chips. A NULL is a real count but not a filterable value (there is no way to say "IS NULL" in a text input or a select), so callers pass only expressible values — the jobs macro does the same via rejectattr('value','none'). Args: label — dimension name shown in the label column values — [{'value': str, 'count': int}], already ordered and filtered.
